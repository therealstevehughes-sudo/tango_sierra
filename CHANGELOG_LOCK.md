## Sprint 001
Date: 2026-07-24
Objective: Add a real persistence layer (drift) and introduce Riverpod as the app's state-management foundation, per the Data storage (Sprint 001) decisions, to replace the in-memory TaskLogStore — without wiring it into task logic, UI, or auth yet.
Files changed:
- pubspec.yaml / pubspec.lock — added drift, drift_flutter, flutter_riverpod, path_provider, path (deps); drift_dev, build_runner (dev deps)
- linux/flutter/generated_plugins.cmake, windows/flutter/generated_plugins.cmake — auto-regenerated by `flutter pub get` to register the `jni` transitive plugin pulled in by drift's native sqlite bindings; no manual edits
- lib/core/storage/app_database.dart (new) — drift table `TaskSubmissions` (id, taskTitle, status, completedBy, completedAt, numericValue, photoAttached, photoPath, notes) and `AppDatabase` (schemaVersion 1)
- lib/core/storage/app_database.g.dart (new, generated) — drift codegen output via build_runner
- lib/shared/models/task_submission.dart (new) — plain `TaskSubmission` domain model (flat shape, matches old TaskLogEntry plus nullable photoPath), storage-technology-agnostic
- lib/shared/repositories/task_submission_repository.dart (new) — abstract `TaskSubmissionRepository` (submit / getAll / getByStaff / getByDateRange / watchAll, append-only, no update/delete) and `DriftTaskSubmissionRepository` implementation
- lib/shared/providers/task_submission_providers.dart (new) — Riverpod providers: `appDatabaseProvider`, `taskSubmissionRepositoryProvider`, `taskSubmissionsStreamProvider`
Files unchanged: lib/main.dart, lib/app/app.dart, lib/features/auth/*, lib/features/tasks/*, lib/features/manager/* (task_log_model.dart / TaskLogStore untouched and still in use) — task logic, UI, and auth were explicitly out of scope for this sprint
Architecture impact: Introduces the repository layer and Riverpod recommended by ARCHITECTURE_LOCK.md, in the shared/ and core/ folders it specifies. Repository interface and implementation both live in shared/repositories/ per this sprint's decision. Model is flat (no TaskTemplate/TaskInstance split), no sync-state fields, no site/area/user linkage — all deferred per logged decisions.
UI impact: none — no screens, widgets, or ProviderScope wiring changed. The new persistence layer exists standalone and is not yet consumed by TaskController or ManagerScreen.
Risks: This layer is currently dead code from the running app's perspective (nothing calls it yet), so it carries no runtime risk, but it also delivers no user-visible improvement until a follow-up sprint swaps TaskController/ManagerScreen over from TaskLogStore to taskSubmissionRepositoryProvider and adds ProviderScope in main.dart. Until that swap, the two storage paths (old in-memory store and new drift database) coexist and must not be conflated.
Deferred items: Wiring TaskController and ManagerScreen to the new repository/providers; adding ProviderScope in main.dart; migrating away from lib/features/manager/task_log_model.dart; template/instance entity split; sync fields; site/area/user linkage; real photo capture (photoPath currently unpopulated by any caller).
Save point name: SPRINT_001_LOCK
