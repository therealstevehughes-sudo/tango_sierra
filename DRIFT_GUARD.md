# DRIFT_GUARD.md

## Purpose
This file exists to prevent:
- loss of product purpose
- architecture drift
- UX drift
- compliance dilution
- random AI improvisation

## Product Essence Reminder
This is not a feature-rich kitchen app.

This is:
- an operational enforcement system
- a compliance control system
- a visibility system for managers and leadership

Staff must act.
Managers must control.
Directors must see.

## Pre-Sprint Drift Check
Before any sprint, confirm:
1. Does this support the core purpose?
2. Does it preserve one-task-at-a-time staff flow?
3. Does it preserve role-based visibility?
4. Does it preserve manager oversight?
5. Does it preserve minimal-friction staff UX?
6. Does it preserve offline-first behaviour?

If any answer is no, stop.

## During Sprint Rules
- do not guess
- do not improvise architecture
- do not make staff screens more complex
- do not turn required tasks into optional tasks
- do not weaken logging or evidence rules

## Post-Sprint Drift Check
Confirm:
- no UI drift introduced
- no architecture drift introduced
- no purpose drift introduced
- no unnecessary feature creep introduced

## Failure Response
If drift occurs:
1. revert to last stable save point
2. identify source of drift
3. correct before moving forward
4. update changelog
